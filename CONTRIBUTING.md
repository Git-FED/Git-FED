# Contributing to FedPromptly

Thank you for helping make the next step clearer for builders.

## Before opening an issue

Search existing issues and discussions. If the idea changes payments, accounts, security, moderation, or legal language, call that out explicitly.

## Good pull requests

A good PR is focused, explains the user problem, includes the expected behavior, and documents how it was tested. Content changes should say which audience they serve. Visual changes should include a screenshot at mobile and desktop widths.

## Content contributions

Use status labels honestly. A concept is not a product. A project is not an endorsement. A metric needs a source and last-reviewed date. If you are unsure, ask for clarification rather than adding hype.

## Payment and security

Never commit secrets, private keys, card data, or production credentials. Do not modify provider IDs, payment scripts, or age-gate behavior casually. Follow `docs/payment-and-age-gate.md` and request review.

## Review standard

Maintainers will prioritize clarity, accessibility, security, truthfulness, and maintainability over decorative complexity.
