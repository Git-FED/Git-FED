# Launch Runbook

## T-14 to T-7: Content freeze preparation

- Confirm the launch message, date, owner, and destination URL.
- Review every project description and link.
- Replace placeholders or clearly label them.
- Check the support inbox and payment provider accounts.
- Confirm the legal reviewer and escalation contact.

## T-6 to T-2: Technical rehearsal

- Run the site locally through a static server.
- Test the GitHub Actions workflow on a branch.
- Test 404 routing and asset paths from the deployed base URL.
- Test mobile width, keyboard navigation, reduced motion, and no-JavaScript copy.
- Confirm payment widgets do not load or expose unexpected controls before the intended gate state.

## T-1: Release candidate

- Create a release candidate tag or commit.
- Capture screenshots of the homepage, project area, support section, and age gate.
- Record the current metrics baseline if analytics is enabled.
- Open a private launch checklist with owner names.

## Launch day

1. Deploy.
2. Verify the public URL from a clean browser session.
3. Verify support email links and external URLs.
4. Publish the launch message.
5. Watch errors, support inbox, provider dashboard, and community discussion.
6. Record issues without hiding them.

## T+24 hours

- Publish what was learned.
- Fix broken links and confusing copy first.
- Thank contributors and early supporters.
- Do not announce numbers until they are sourced and reviewed.
