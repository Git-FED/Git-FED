# Page Specifications

## Homepage

**Job:** orient a stranger and create a first action.

**Required sections:** hero, four ecosystem pathways, selected projects, support, footer contacts.

**Hero acceptance criteria:**

- The first screen says what FedPromptly is without requiring a scroll.
- The primary CTA leads to real content.
- The secondary CTA does not compete with the primary action.
- The visual atmosphere is futuristic but the words are plain.

## Project catalog

**Job:** give visitors examples and starting points.

Each project needs a name, type, description, status, owner or builder, link, and last reviewed date. A `#` URL is not acceptable for a public released project; use `Concept` status until a real destination exists.

## Support area

**Job:** explain what support enables without using pressure.

It should distinguish one-time support, subscriptions, and community participation. The payment section should not be the first thing a visitor sees. Add cancellation, refund, tax, and receipt information once verified.

## 404 page

**Job:** turn an error into orientation.

It should explain that the path is missing, give a home link, and optionally offer the project catalog or docs. Do not present a dead-end error code alone.

## Footer

Every full page footer should include:

- FedPromptly name and one-sentence identity
- careers, support, business, and contact email links
- verified support links
- privacy/terms links when those pages are ready
- copyright/license line

## Mobile and low-resource requirements

- Content works at 320px wide.
- No horizontal scrolling.
- Tap targets are comfortably sized.
- Background effects do not block interaction.
- The page remains understandable if external fonts or widget scripts fail.
