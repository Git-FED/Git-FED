Public direction

Build the map, then build the world.

The roadmap is directional. Items become active when they have a problem statement, owner, smallest useful slice, and public status.

01 / Now

Make the front door useful

Clarify the mission, connect the four pathways, maintain an honest project catalog, publish support routes, and make the site accessible.

Done means: a first-time visitor understands the project in 30 seconds and chooses a real next action.

02 / Next

Make building visible

Publish starter templates, build logs, Labs entries, project submissions, and recurring Build Nights or an asynchronous equivalent.

Done means: “I do not know what to build” leads to a concrete starting point.

03 / Later

Make contribution durable

Add maintainer ownership, release practices, proof-based verification, and carefully reviewed creator economics.

Constraint: no marketplace or payout promise before legal, tax, licensing, fraud, and payment work is complete.

04 / Future

Explore infrastructure concepts

FedSense, FedAPK, FedNet, and FedOS are long-horizon concept areas. They need technical definitions and evidence before being described as products.

A changed roadmap is healthier than a silent promise.

Read the detailed rationale and review questions in the repository roadmap.
